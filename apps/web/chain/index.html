How it works

Four links, one chain

01

A local ID

Your browser makes a random 32 character ID and keeps it. No fingerprinting, nothing tied to you.

02

A session record

Each transfer logs its route, file types, sizes and SHA-256 hashes. Never names, never contents.

03

A hash link

Every record carries the hash of the one before it, so the chain is append only and tamper evident.

04

A public view

Anyone can browse the ledger below: routes, timings, file categories and status timelines.

The boundary

Chain is public, Vault is not

The chain exists to make deliveries checkable. Vault exists to keep things private. They never mix

What the chain records

  • Route taken, direct or local
  • File category, type and size
  • A SHA-256 hash of each file
  • Status changes and their times
  • The hash of the previous record

What it never records

  • File names or file contents
  • IP addresses
  • Vault notes, folders or secret links
  • Anything that names a person
